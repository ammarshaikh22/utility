# Comments for package-lock.json

This is a sidecar annotation file for `package-lock.json` so we can add human-friendly comments without changing the JSON (JSON does not support comments and changing `package-lock.json` can break npm determinism).

Summary (from this repo's `package-lock.json`):
- name: `public_html`
- lockfileVersion: `3`
- requires: `true`

Why a sidecar file?
- JSON (the format of `package-lock.json`) doesn't support comments.
- Modifying `package-lock.json` directly may break npm/yarn integrity checks.
- A sidecar Markdown file preserves the original file and adds documentation you can update freely.

Top-level structure explained

- `name` — the project/package name.
- `lockfileVersion` — the format version of the lockfile. npm v7+ uses v2, newer npm uses v3. Keep this intact.
- `requires` — boolean indicating whether the top-level `package.json` had `dependencies`/`devDependencies` used.
- `packages` — (lockfile v2/v3) a map that mirrors the node_modules layout and contains metadata for each installed package. Keys are paths, `""` is the project root (your top-level dependencies are listed under `packages[""]` as `dependencies` and `devDependencies`).
- `dependencies` — (older lockfile forms) a map of top-level dependency entries (in v3 you still have `dependencies` collated under `packages` and a `dependencies` object).

Important fields inside each package entry (example keys you'll see around this repo):
- `version` — the resolved version npm has installed (e.g., `7.18.13`).
- `resolved` — the tarball url that npm downloaded from (useful for audits/debugging).
- `integrity` — Subresource Integrity hash ensuring the contents are identical; do not change.
- `dev` — if true the package is only a dev dependency.
- `optional` — true if package is optional.
- `dependencies` — nested dependencies required by that package (maps to other `node_modules/…` entries).
- `peerDependencies` / `engines` — constraints from the package that can affect install behavior.
- `funding` — optional metadata pointing to donation pages.

How to find a package and read its entry
- Search for `"node_modules/<package-name>"` in the lockfile for package-level metadata. Example: `node_modules/@babel/core`.
- The project root metadata is under `packages[""]` — this is where your project's direct `dependencies` and `devDependencies` are recorded.

Notes on safety and edits
- Do NOT manually edit `version`, `resolved`, or `integrity` fields. Doing so can break installs and security verification.
- Prefer editing `package.json` and running `npm install` or `npm ci` to update `package-lock.json` safely.
- If you want inline comments in a working copy, consider:
  - Keeping this Markdown sidecar (recommended), or
  - Creating a `package-lock.json.cjson` / `package-lock.json.jsonc` copy (JSONC supports comments), but **do not** use that copy as the real lockfile for npm installs.
